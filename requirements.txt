# Most of this file is deliberately unpinned: a patch release of aiofiles or lz4 is
# not worth a commit. The bounded entries below are the exceptions, and they are
# bounded for one reason — nothing here is resolved when a file changes, it is
# resolved when the image is built. A long-lived container and a fresh build can
# therefore sit on different majors with no diff to show for it, which is how a bare
# `sqlalchemy` put 2.0 in production and 2.1 in the next build.
#
# So: libraries that define a contract this tree is written against — the DB schema
# and migration behaviour, request/response validation, route semantics — carry an
# upper bound at the next breaking version. The lower bound is the oldest release
# known to work here, not a guess. Everything else floats.
#
# Raising a bound is a deliberate act: do it in its own commit, with both suites run
# against the new version, never as a side effect of an unrelated rebuild.
aiofiles
aiopath
imagehash
pybktree
aiosqlite
# Owns schema migrations; a major rewrites how revisions are generated and applied.
alembic>=1.20,<2
dacite
debugpy
# Pre-1.0, so its minors are the breaking ones: route and dependency semantics
# move there, and `Payload`/alias handling across every endpoint rides on them.
fastapi>=0.142,<1
ffmpeg-python

jinja2
jstyleson

# Capped because onnx 1.23 emits IR version 14 and NO released onnxruntime reads it —
# 1.30.0, the newest, still caps at IR 13 (verified against each of 1.26/1.27/1.28/1.30).
# 1.22.0 is the newest onnx anything can consume. Unpinned, the ONNX this tree *writes*
# — a converted upload, a training export, a test fixture — stops loading in the
# inference server, surfacing far from here as "Unsupported model IR version".
# This is NOT coupled to the onnxruntime <1.27 caps: raising those fixes nothing. Lift
# this only once a runtime ships IR 14 support; re-check with onnx.helper.VERSION_TABLE.
